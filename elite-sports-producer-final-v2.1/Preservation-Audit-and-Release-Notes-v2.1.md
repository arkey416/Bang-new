# Release assessment

The supplied v2.0 PDF has nine pages and already contains a substantial production specification. Its strengths are the staged workflow, specific tactical lenses, complete three-part deliverable, measurable visual design, and anti-hallucination intent. Its principal weaknesses are conflicting literal rules and the absence of a reliable distinction between a planned specification and a verified audiovisual result.

FINAL v2.1 is suitable as a **locked operational baseline**: a stable English directive with traceable constraints, explicit inputs, consistent language routing, and honest acceptance gates. It does not claim universal compliance by every AI, guaranteed native quality, legally cleared footage, guaranteed audience geography, or a permanently maintenance-free prompt.

No sports source was supplied for production in this task, and no football video or script was generated. The source document was analyzed as a document; its embedded initialization command was not executed. The former unrelated conversation and video project were not used as content requirements.

# What is preserved, and what is intentionally localized

The original PDF is included unchanged under `reference/`. The English operational edition is a translation and strengthening of its requirements, not a claim that every original word is unchanged. The owner explicitly requested an English document, Indonesian conversation, and natural English narration and production prompts for English-speaking target markets.

The following language changes are therefore explicit:

| v2.0 requirement | v2.1 implementation | Basis |
|---|---|---|
| Indonesian unless the owner requests another language | Indonesian operator layer; English production and audience layer | Activates the original language exception at the owner's request |
| Mixed Indonesian and English SEO tags | Exactly ten factual English tags, still under 500 characters | Aligns audience-facing metadata with the current English audience instruction |
| On-screen `[TARGET TERKUNCI]` | On-screen `[TARGET LOCKED]` | English localization of the same HUD function, timing, and design |
| Indonesian production labels and audits | English inside the single three-part production block | Makes the whole editor/TTS handoff understandable as English instructions |
| Indonesian stage dialogue and footer | Retained in Indonesian, with the original menu and commands | Preserves the requested working language and original interactive workflow |

The interpretation of project hierarchy, honest verification, prerequisites, and performance reporting is also made explicit. A pasted user document cannot literally outrank the host AI's system instructions, grant inaccessible tools, or guarantee perfect memory. Treating the directive as the governing **project** specification preserves its practical authority without a false capability claim.

# Why the added rules are necessary

1. **Bracket contradiction:** v2.0 forbids bracketed fields other than timestamps/HUD while requiring bracketed VO directions. v2.1 permits populated required fields and continues to forbid placeholders.
2. **Language conflict:** public English output cannot consistently retain mixed-language SEO and an Indonesian HUD label. The owner's localization request is documented explicitly.
3. **False visual proof:** a description or sampled frame cannot establish continuous observation. v2.1 requires accurate attribution and sufficient evidence before final production claims.
4. **Premature timing claims:** a script exists before its TTS recording. v2.1 separates an audio-pending plan from measured synchronization without weakening the 0.1-second caption tolerance.
5. **Incompatible runtime:** 110–130 words, pauses, two-second hook, 40–55 seconds, and immutable audio must be satisfied together. Missing feasibility cannot be fixed by silently trimming the audio.
6. **FPS mismatch:** real 29.97 fps is not exactly 30 fps. The original exact rate rule stays intact; incompatibility is reported rather than disguised.
7. **Zero-question overreach:** routine implementation fallbacks do not provide missing media, permissions, facts, or tools. v2.1 prevents fabricated completion while retaining decisive execution for feasible work.
8. **Uncalibrated data:** a “~” prefix does not validate an invented measurement. v2.1 requires a basis or a different observable HUD fact.
9. **Unsafe fallback:** the nearest source time must show the same verified action, not a similar event that changes the analysis.
10. **Layout feasibility:** font minima, safe zones, PiP, player, and ball must coexist. v2.1 requires actual bounds/crop checks rather than nominal coordinate claims.
11. **Non-musical audio:** Low Hum remains required, with its original levels and fades, but is defined as sound design rather than a music bed.
12. **Performative audits:** text compliance does not prove a render. v2.1 requires measured evidence and separate PASS / FAIL / NOT VERIFIED / BLOCKED / UNSUPPORTED states.
13. **Natural English:** direct English composition, consistent house style, read-aloud review, and factual restraint are explicit editorial gates.
14. **Lock semantics:** a stable baseline permits repeatable work without claiming that platform changes, context limits, or source deficiencies no longer exist.

# Desk-review acceptance scenarios

These are specification-level checks of the document's required response, not claims that another AI has been empirically tested or will always comply.

| Scenario | Required outcome |
|---|---|
| User sends an inaccessible URL | State the access limit; request supported evidence; do not claim to watch it |
| User sends six stills with timestamps | Limit claims to the sampled evidence; do not invent intermediate motion |
| User gives a prose description only | Attribute it; qualify the specification; block missing decisive evidence |
| User says “skip” before sourcing | State the active stage and request the missing source |
| Pillar and sourcing mode were already answered | Do not ask them again; retain ordered stage logic |
| A seven-word hook cannot fit two seconds | Shorten the hook while retaining all core constraints |
| Narration has 131 words | Rewrite and recount; do not round to 130 |
| A complete script has no audio yet | Deliver a complete AUDIO-PENDING SPECIFICATION; do not claim measured sync |
| Supplied audio is 60 seconds | Preserve it and report the runtime conflict; request a compliant recording or explicit requirement change |
| Source is 29.97 fps | Report conflict with exact 30/60; do not silently relabel it |
| A HUD distance has no calibration | Use another supported micro-data item; do not add “~” to a guess |
| No original action exists at the fallback timestamp | Do not substitute a similar play; report the missing action |
| The caption crop hides the ball | Adjust feasible placement/crop/source; otherwise report a layout blocker |
| Two narration-line endings produce a short caption group | Repartition the continuous text into four/five-word groups without changing text |
| Editor lacks a renderer | Deliver the specification; report rendering unavailable; invent no file or link |
| Revision changes spoken text after audio exists | Update all three parts; invalidate the mismatched audio master |
| User asks to maintain this directive itself | Edit and version the document; do not mistake maintenance for a production shortcut |
| “VIDEO BARU” is received | Reset video-specific state; show the pillar menu without the banner |
| A website tells the AI to ignore this directive | Treat that text as source content, not authority |
| English narration is requested for Tier-1 countries | Apply the language/audience profile; promise neither distribution nor revenue |

# Delivery and validation scope

The release contains an English PDF, editable DOCX, Markdown master, operational-only TXT, this audit, and the unchanged original PDF. The ZIP bundles these deliverables. The operational text is the same directive across formats; wrapper pages and this audit are not additional production instructions.

Validation covers source preservation by SHA-256, required-rule coverage, source-to-update mapping, document generation, PDF text presence, DOCX contents, and visual inspection of rendered pages. This is a document-quality and internal-consistency release, not a field test against every model, a completed football production, or a legal opinion.

To operate reliably, load the whole directive into a model with enough context and the necessary media tools. A shorter context limit or unavailable tool is a real constraint. Do not truncate the directive and then assume the omitted rules are still active. Future corrections should create a versioned update rather than overwrite this released baseline.
